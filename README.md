# PetShelter REST API

Первая версия REST API на основе ветки `mentor`, коммит
`a444be3d3f02e0d72c1ec61ce1767b4d0cf8c256`. Используется стандартная библиотека Go.

## Что уже было в mentor

HTTP-сервер и `GET /clinics/`, пример разделения на controller/service/models.
Контроллеры и сервисы собак и приютов были заготовками. Консольные сценарии
и исходные демонстрационные данные сохранены.

## Запуск

Нужен Go версии 1.26.3 или новее — требование исходного `go.mod` сохранено.
В терминале из корня проекта:

```sh
go run ./cmd/petshelter
```

Открой `http://localhost:8080/dogs` или `http://localhost:8080/clinics/`.
Остановить сервер: Ctrl+C. Приложение ожидает завершения активных запросов
до 5 секунд. Ошибка запуска, например занятый порт, возвращается в main.

По умолчанию сервер слушает `localhost:8080`. Изменить адрес в PowerShell:

```powershell
$env:HTTP_ADDR = "localhost:8081"
go run ./cmd/petshelter
```

## Адреса и действия

| Метод | Адрес | Действие | Успех |
|---|---|---|---|
| GET | /dogs | Все собаки | 200 |
| GET | /dogs/{id} | Одна собака | 200 |
| POST | /dogs | Добавить собаку | 201 + Location |
| PUT | /dogs/{id} | Полностью обновить поля собаки | 200 |
| DELETE | /dogs/{id} | Удалить собаку | 204 без тела |
| GET | /clinics | Все поликлиники | 200 |
| GET | /clinics/{id} | Одна поликлиника | 200 |
| GET | /shelters | Все приюты | 200 |
| GET | /shelters/{id} | Один приют | 200 |

Адреса коллекций работают и с завершающим `/`, включая исходный `/clinics/`.
Для отдельного объекта используй `/dogs/1` без завершающего `/`.
Приюты и поликлиники пока являются справочниками только для чтения.

## Добавление собаки

В Postman: метод POST, адрес `http://localhost:8080/dogs`, Body → raw → JSON.
Заголовок: `Content-Type: application/json`.

```json
{
  "nickname": "Бобик",
  "age": 2,
  "weight_kg": 12.5,
  "check_in_date": "2026-09-09",
  "shelter_id": 1,
  "clinic_id": 2
}
```

Ответ содержит эти поля и сгенерированный `id`. Заголовок `Location` указывает
адрес нового объекта. Для PUT отправляй те же шесть полей целиком; ID задаётся
в адресе. Кличку можно менять, ID остаётся прежним. Одинаковые клички допустимы.

PowerShell, без необходимости вручную экранировать JSON:

```powershell
$body = @{
    nickname = "Бобик"
    age = 2
    weight_kg = 12.5
    check_in_date = "2026-09-09"
    shelter_id = 1
    clinic_id = 2
} | ConvertTo-Json

$dog = Invoke-RestMethod -Method Post -Uri "http://localhost:8080/dogs" -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
Invoke-RestMethod -Uri "http://localhost:8080/dogs/$($dog.id)"
Invoke-RestMethod -Method Delete -Uri "http://localhost:8080/dogs/$($dog.id)"
```

## Проверка данных и ошибки

Все шесть полей обязательны. Возраст — целое число от нуля; вес — положительное
число; дата — существующая календарная дата YYYY-MM-DD. Приют и поликлиника
должны существовать. Их ID можно получить через GET соответствующего справочника.
Пустая кличка и неизвестные JSON-поля отклоняются. Возраст и вес передаются
числами, а не строками. Тело запроса ограничено 1 МиБ.

Ошибки имеют форму `{"error":"описание"}`:

- 400 — неправильные поля, JSON или ID.
- 404 — объект или маршрут не существует.
- 405 — метод не поддерживается; допустимые методы указаны в `Allow`.
- 413 — слишком большое тело запроса.
- 415 — требуется `Content-Type: application/json`.
- 500 — внутренняя ошибка сервера.

В ответах поликлиник сохранены прежние имена полей `NumberClinic`, `Address`,
`PhoneNumber`, `WorkingTime`, добавлено поле `id`. Приюты аналогично используют
`NumberShelter`, `Address`, `Number`, `WorkingTime` и `id`.

## Как устроен код

1. `cmd/petshelter/main.go` запускает приложение и принимает сигнал остановки.
2. `internal/app/app.go` собирает общее хранилище, сервисы, контроллеры и сервер.
3. `internal/controller/router.go` связывает метод и URL с обработчиком.
4. Контроллер читает запрос, вызывает сервис и формирует HTTP-ответ.
5. Сервис проверяет данные и выполняет операцию с хранилищем.
6. `internal/models` описывает данные для HTTP API.

Например, POST /dogs проходит через `Dog.Create` → `service.Dog.CreateDog`
→ общее хранилище → ответ 201 с JSON. Следующий GET читает уже созданную запись.
`sync.RWMutex` защищает данные собак при одновременных HTTP-запросах.

## Ограничения первой версии

Данные находятся в памяти. После перезапуска изменения исчезают, восстанавливаются
исходные примеры. Их необычные значения (например, возраст 643) не исправлялись
без подтверждения владельца. Предельный допустимый возраст требует отдельного
бизнес-правила. Авторизации и базы данных пока нет. Это локальная учебная версия.
Удаление собаки означает удаление записи; отдельная история пристройства не ведётся.
Консольная и HTTP-модели пока существуют отдельно; начальные данные HTTP берутся
из исходного `internal/data.go` через преобразование в `service/store.go`.
